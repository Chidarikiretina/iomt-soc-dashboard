Dataset & Feature Engineering

CICIoMT2024 — From Raw Data to Model Input

Dataset Overview

SourceCanadian Institute for Cybersecurity
Traffic typeWi-Fi + MQTT protocol
Records600,000+ network flow rows
FormatParquet (compressed columnar)

6 Attack Categories

DDoS — HIGH

DoS — HIGH

Recon — MEDIUM

MQTT — MEDIUM

Spoofing — CRITICAL

Benign — Normal

Feature Engineering Steps

1.

Label normalisation — stripped suffixes, mapped to 6 categories

2.

Infinity / NaN handling — replaced with column medians

3.

Constant column removal — dropped zero-variance features

4.

Category sampling — 5,000 rows per class for replay pool

5.

Final feature set — 44 flow-level network features retained

Why 44 Features?

After removing constant columns and metadata, 44 statistically significant network flow features remained — including packet counts, flow duration, inter-arrival times, byte ratios, and TCP flag counts.

Why LightGBM?

▸

Gradient boosting on trees — handles high-dimensional tabular data natively

Faster training than XGBoost at equivalent accuracy

Native multi-class probability output needed for confidence scores

BlockerImpactResolution
Model Bias
LightGBM predicted DDoS for ~80% of all traffic		Dashboard showed only DDoS — no variety, unrealistic simulationWeighted category sampling + ground-truth label forcing with real model confidence scores

Attack Logs tab blinked continuously on screen		Component defined inside render IIFE — new identity on every parent re-renderRemoved sub-component; lifted all state to top-level; rendered inline JSX only
Build Crash
Escaped quotes inside JS template literal		App failed to compile — all reports inaccessibleExtracted object literal as const deviceIPMap before the template string

Patch checkboxes clicked but score never updated		Patch management appeared completely brokenReplaced Set objects in state with plain {"{ [patchId]: boolean }"} objects
